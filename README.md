# Prompt Keeper

一个 [SillyTavern](https://github.com/SillyTavern/SillyTavern) 扩展，用于按聊天保存和恢复 Chat Completion Prompt Manager 的条目启用状态、排列顺序以及当前活跃预设。

## 功能特性

- **按聊天独立保存**：配置写入当前聊天元数据，不同聊天互不影响。
- **完整 Prompt 配置**：保存条目的启用/禁用状态、排列顺序和当前 Chat Completion 预设。
- **多槽位**：同一聊天最多保存 5 个配置槽位；可选择在保存时自定义名称。
- **自动恢复**：切换聊天时可自动恢复合适的保存槽位，并带有防抖、状态检查和有限重试。
- **手动管理**：可手动保存、选择并恢复槽位，或删除已有槽位。
- **状态提示**：操作栏会提示当前聊天是否已有保存配置。
- **热重载**：扩展入口重新执行时会自动加载新代码，也可在浏览器控制台执行 `window.PromptKeeperReload()`。

> Prompt Keeper 只管理 Chat Completion Prompt Manager。它不管理世界书、模型、API 连接、生成参数、Instruct 预设、上下文模板或 SillyTavern 核心文件。

## 安装

### 通过 SillyTavern 扩展安装器

1. 打开 SillyTavern。
2. 进入 **扩展面板** → **安装扩展**。
3. 粘贴仓库地址：

   ```text
   https://github.com/sisjzknxhnsnejxn-cmyk/prompt-keeper
   ```

4. 点击安装。
5. 首次安装或启用后刷新一次浏览器页面。

### 手动安装

```bash
cd /path/to/SillyTavern/data/<user-handle>/extensions
git clone https://github.com/sisjzknxhnsnejxn-cmyk/prompt-keeper
```

安装完成后刷新浏览器页面。

## 使用方法

插件会在 Prompt Manager 附近加入操作栏：

| 按钮 | 功能 |
|------|------|
| 保存 | 保存当前条目状态、排序和预设；本次保存的槽位会成为默认槽位 |
| 恢复 | 从当前聊天的已有槽位中选择并恢复；恢复时可切换到槽位记录的预设 |
| 删除 | 选择并删除当前聊天中的保存槽位 |

默认情况下，槽位名称使用当前预设名称。同名槽位再次保存时会更新该槽位；启用“保存时允许自定义名称”后，可为同一预设保存多个不同槽位。

## 设置

| 选项 | 说明 |
|------|------|
| 启用插件 | 控制 Prompt Keeper 的保存、恢复和自动恢复功能 |
| 切换聊天时自动恢复 | 开启后，在切换到有保存配置的聊天时自动恢复 |
| 保存时自定义预设槽位名称 | 开启后，保存时询问槽位名称；关闭时使用当前预设名称 |
| 槽位选择弹窗配色 | 支持浅色护眼（米白卡片 + 深棕文字）与深色玻璃两种配色方案 |
| 自动恢复延迟 (毫秒) | 切换聊天后等待多久再执行恢复（300~5000ms，默认 1500ms） |

自动恢复会优先寻找与当前预设匹配的槽位；找不到时使用该聊天的默认槽位。若当前状态已经与存档一致，插件不会重复应用配置。

## 保存范围与兼容行为

Prompt Keeper 保存：

- Prompt Manager 条目的启用/禁用状态；
- 已保存条目之间的相对顺序；
- 保存时使用的 Chat Completion 预设名称；
- 槽位名称和保存时间。

恢复时，当前预设中新增加且存档中不存在的条目会被保留，不会仅因旧存档缺少它们而被删除。存档中存在、但当前预设已不存在的条目无法恢复，会被跳过。

## 数据保存位置

配置保存在当前聊天的元数据中：

```text
chatMetadata.promptKeeperState
```

数据会跟随聊天文件保存。导出或迁移聊天时，只有在聊天元数据被完整保留的情况下，Prompt Keeper 配置才会一同保留。

内部的 `promptKeeperState.version` 是存档结构版本，与插件发布版本 `2.1.1` 不是同一个概念。

## 系统要求

- SillyTavern 1.12.0 或更高版本。
- 使用 Chat Completion API，并且前端可正常访问 Prompt Manager 数据。

## 常见问题

**Q：数据保存在哪里？**

A：保存在当前聊天的 `chatMetadata.promptKeeperState` 中。

**Q：为什么某些条目没有被恢复？**

A：如果条目不在当前预设中，插件会跳过它；当前预设后来新增的条目则会被保留。

**Q：自动恢复会选择哪个槽位？**

A：优先使用与当前预设匹配的槽位，否则使用当前聊天的默认槽位（通常是最近一次保存的槽位）。

**Q：更新后需要重启 SillyTavern 后端或手动刷新页面吗？**

A：不需要。SillyTavern 更新扩展并重新执行入口后，插件会自动清理旧运行时、载入新版文件并立即恢复界面；如果热重载失败，会自动刷新页面一次作为兜底，并防止循环刷新。也可以在浏览器控制台手动运行 `window.PromptKeeperReload()` 触发热重载。
